Setting `strongControlBorders` (boolean, default true), persisted the way `musicEmbedTag` is: default in `backend_service/helpers/settings.py` (near line 268) and the loader (near line 381), read and update in `backend_service/state/settings_state.py` (near lines 109 and 151), `strongControlBorders: bool | None = None` in the request model in `backend_service/models/__init__.py` (near line 265), and both interfaces in `src/types/settings.ts`.

### R8. FU-165 studio time estimates scale with size, frames and steps

Model: `seconds = catalog x (fixed + (1 - fixed) x steps/ref_steps x w(T)/w(T_ref))`, `w(T) = T + T^2/quad`, `T = W/16 x H/16 x F/4` (images: F = 1). Measured on the 4090 for Wan: `fixed = 0.04`, `quad = 53300`.

Steps:

1. New `backend_service/helpers/time_estimate.py` (pure, no heavy imports): `scaled_seconds(catalog_seconds, ref, width, height, frames, steps, fixed=0.04, quad=53300) -> float | None`. Returns the flat catalog figure when a reference is missing, and never raises. Mirror it in `src/utils/timeEstimate.ts`. Both read the same cases from `tests/fixtures/time_estimate_cases.json` so the two cannot drift. First case: Wan 2.2 TI2V, 275 s at 1280x704x121 and 20 steps, asked for 832x480x49 at 20 steps, expect 32.5 s (measured 34.5; tolerance 6 %).
2. Reference per row: add `estimateRef: {"width", "height", "frames", "steps"}` (and optional `"fixed"`, `"quad"`) to rows in `image_models.py`, `video_models.py`, `video_ltx25.py`. Fill it from what the figure was measured at; where the row does not say, derive width and height from `recommendedResolution`, frames from `defaultDurationSeconds` x fps + 1, steps from the matching entry in `backend_service/catalog/recommended_settings.py` (`_ENTRIES`) or the row's `defaultSteps`. A row with no trustworthy steps reference gets no `estimateRef` and stays flat. Write the source of each reference in a comment or `note`. TI2V 5B is 20 steps.
3. Constants per engine: video on CUDA diffusers uses the Wan fit. For LTX the fit was 15 % low at 49 frames: measure and set `fixed` for the LTX rows. **Images need their own `fixed`** (Klein: about 0.6 with these numbers; mflux has no offload swap, so the Mac value differs). Measure on the M4 Max: for each installed image family (mflux rows, one sd.cpp row) and for LTX-2.5 q4, run two sizes and two step counts warm (four runs each), solve for `fixed`, store it in the row's `estimateRef`, and write the runs to `docs/research/time-estimate-fit-2026-11.md`. Rows not measured keep the engine default and show the basis "estimated".
4. Apply: `ImageStudioTab.tsx` line 1043 and `VideoStudioTab.tsx` line 1233 pass the scaled value from the current width, height, frames and steps; `backend_service/storyboard/estimate.py` (the catalog branch at lines 102 to 110) scales by the project's size and the shot's frames instead of duration only; `backend_service/mcp_bridge/tools.py` lines 340 and 431 pass the scaled value to `STORE.submit(estimate_seconds=...)` so the job ETA matches. `backend_service/helpers/fit.py` keeps comparing rows at their reference settings (no change).
