# v0.10.0 closing improvements (eight items from the QA and UX pass)

Owner decision (2026-11-16): do all eight in 0.10.0, not 0.11.0. Logged as D-84.

Challenge, said once: item 8 (the long music video, S14) was sized at 2 to 3 weeks. It goes in at a reduced first cut: the parts that make a long project safe and useful (a queue that survives a restart with pause and resume, a song attached to a project with a cut plan from its sections, lyric captions, and a freestyle board view). Lip-sync, character consistency across 60 shots and a generated song inside one button stay out. Label: costly. Alternative if it slips: ship the queue, captions and cut plan, and keep the board view for 0.11.0.

Base: `release/v0.10.0`. One git worktree and one branch per agent (`v0100/<package>`), merged back by the integrator after the Mac check. Integrator-only files: `FOLLOW_UPS.md`, `docs/hub/*`, `CLAUDE.md`. Each agent keeps `docs/progress/v0100-<package>.md`.

## The eight items

1. Chat plan card: a pending card survives a reload; a running thread shows its real title; a refused first tool call shows as a visible notice the model and the user can both act on. (S-J)
2. Keyboard use of a film: one tab stop per shot card, arrow keys move between cards and inside a card; about 250 stops for 30 shots becomes about 10. (S-K)
3. First-run pass buttons: on a fresh planned film one pass button is primary; Make drafts is primary when the still model is slow. (S-K)
4. Slow default still model: show the time per still in the project defaults ("about 10 min per still") with a one-click "use the fast model". (S-K)
5. Plan tab suggests a shot count and a length from the brief ("a 30 s ad is 6 to 8 shots"). (S-K)
6. A clean-up panel in Settings lists projects, chat threads and gallery images with size and date; the user ticks what to delete; a confirm names the count and says it cannot be undone. Nothing is guessed to be test data. (S-L)
7. Redo still with explicit shot ids refuses shots that have no take, like the form without ids. (S-K)
8. Long projects: (S-M1 backend, S-M2 board)
   - a queue that survives a restart, with pause and resume;
   - a song attached to a project, sections and beats found from the audio, a cut plan from them;
   - lyric captions burnt in and written as `.srt`;
   - a freestyle board view: pictures as cards on a canvas, a chat per card, one board chat, "order these" into the timeline.

### S-L. Clean-up panel (item 6). Agent: sonnet
Files: new `src/features/settings/CleanupPanel.tsx`, a route module `backend_service/routes/cleanup.py`, helpers it needs, tests, `src/locales/*/settings.json`.
- `GET /api/cleanup/items` lists: storyboard projects (name, shots, size on disk, last edited), chat threads (title, messages, last used), gallery images and videos (name, size, date). `POST /api/cleanup/delete` takes the chosen ids and deletes them; paths come only from the backend's own lists (never a path from the request); a project in use by a live batch is refused.
- The user ticks items; confirm dialog names the count and total size and says it cannot be undone. Default: nothing ticked.
- Treat every id as hostile (the repo's path rules). No "test data" guessing.

### S-M1. Long projects, backend (item 8). Agent: opus
Files: `backend_service/storyboard/{batch,store,models,ops,captions,render_plan,longrun}.py`, new `song.py` and `cutplan.py`, routes under `backend_service/routes/storyboard*.py`, tests, e2e phase 20 additions, progress file.
- Durable queue: a batch record keeps its remaining steps; on start-up an interrupted batch becomes `paused` (not `cancelled`) and `POST .../batches/{id}/resume` continues it; `POST .../batches/{id}/pause` stops after the current step. The S3 reconcile is kept for steps that cannot resume.
- Song: `Project.song` (path under the project's media, seconds, bpm, sections `[ {start,end,label} ]`, beats), `POST .../song` attaches from the Music library or a file (picture rule: check bytes), analysis uses what the bundled ffmpeg and numpy give (no new dependency; licence rule in CLAUDE.md).
- Cut plan: `POST .../cut-plan` proposes shots from sections and beats (lengths follow the music, capped by the video model's clip length), returned as a plan the Plan tab can apply; applying is an ordinary op with Undo.
- Lyric captions: lines with timing from the song's sections or from speech-to-text alignment when the STT model is installed; burn-in and `.srt` use the existing caption look.
- Contract for S-M2 is written first in `docs/progress/v0100-m1.md` (routes, JSON shapes) and committed early.
