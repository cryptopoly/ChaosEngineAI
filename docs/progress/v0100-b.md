# v0.10.0 package S-B: draft and final passes, faster default still (S2, S6)

Branch `v0100/b` (from `release/v0.10.0`). Plan: `docs/plans/v0.10.0-storyboard-polish.md`, section S-B.

## Done

### S2 Faster default still model
- `backend_service/mcp_bridge/models.py`: image rows carry `secondsPerStill` (catalogue time at 1280x720, from
  `estimateRef`). `default_model(state, "image")` now picks the fastest installed, fitting, not territory-limited
  model by that figure (rows without one fall back to catalogue order). New `quality_model`: the old rule (catalogue
  best-fit order), used for the final pass. Video and other kinds are unchanged.
- One rule: the agent's default, the storyboard Automatic choice (`_pick_variant` with no model) and the new route
  `GET /api/storyboard/still-models?width&height` all go through `default_model` / `quality_model`.
- Project settings (Overview): the image model select shows "Automatic: fastest (name)", every model with
  "about N per still" at the project size, and a hint line under it. New "Final pass image model" select
  (`Defaults.finalImageModel`, Automatic = best quality).
- Existing projects with a saved image model keep it. Projects saved with no image model (Automatic) now resolve to
  the fastest model too: that is the point of the change, but it is a behaviour change for those projects.

### S6 Draft then final
- Model: `Take.renderPass` (`draft` | `final`, default final, so older takes read as final), `Shot.kept`,
  `Defaults.finalImageModel`, `BatchRecord.what` gains `final`, `BatchRecord.draft`. No schema version bump
  (optional fields with defaults); an older app build refuses a project saved by this one (unknown fields).
- Op `set_kept {shotId, kept}` (revision-checked, reversible: undo and redo work).
- Batch: `draft=True` hands the generators a copy of the project at the draft size (half, multiples of 64, at
  least 256, never under the model's `minSide`, never above the project size; computed per still and clip model in
  the route). `what="final"` works on kept shots without a finished final take (`needs_final`), makes the still
  with the quality model at the project size, unloads, then the clip from the new still. A final clip never
  completes a draft still-only take. The stored project is never changed by a pass.
- Estimate: measured times count only for takes of the same pass. Route answer keeps every old field and adds
  `stillSeconds`, `clipSeconds` and `passes: {draft, final}` (each: shots, stills, clips, seconds, stillSeconds,
  clipSeconds, basis, imageModel, videoModel, width, height; final adds `assumedAllKept`). Request accepts
  `what: "final"` and `draft`. For agent A: the plan card can read `passes`.
- UI: run bar gets "Drafts with clips", "Make drafts · about N" and "Final pass on N kept shots · about N", with
  the model and size in the tooltip. Shot cards get "Keep for final" (pressed state) and a "Draft" badge. Export's
  "Before you export" list warns when an active take is a draft (`board.exportDrafts`).
- Strings: en plus null placeholders in the other locales, all under `board.*`.
