# v0.10.0 package S-C: honest state after a crash and a busy engine (S3, S4)

Branch `v0100/c`, from `release/v0.10.0`. Plan: `docs/plans/v0.10.0-storyboard-polish.md`, package S-C.

## Done

- S3 No stale "running". `reconcile(project)` in `backend_service/storyboard/store.py` replaces the old first-load-only reset.
  It runs on every `ProjectStore.load` (cheap dry check first, write only when something changes) and, for every
  project on disk, from the app start-up hook (`_lifespan` in `backend_service/app.py`, on a background thread, through
  `ProjectStore.reconcile_all`). A shot left queued or running goes to `done` if it has an active take, else `idle`
  (the rule a finished batch uses); its batch record becomes `interrupted` with `finishedAt`; its queued or running
  results become `cancelled` with a short note. A batch id in `LIVE_BATCHES` (and the shots in its results) is never touched.
  The old once-per-process `_RECOVERED` set is gone (also removed from `bundle.py`, which only added to it).
- S4 Busy engine. `active_generations()` in `backend_service/state/payloads.py` reads the three shared progress
  trackers (image, video, music; three locked dict copies, thumbnail left out) and `workspace()` adds the list as
  `system.activeGenerations` (new optional field, nothing existing changed). The frontend already polls the workspace
  every 2 s, so there is no new request. `src/utils/busyEngine.ts` turns a run into "Image engine busy: <run label> ·
  step X of Y" (also Video and Music). Shown in the sidebar footer (instead of "No model loaded"; beside the model name
  when a chat model is loaded), the Dashboard "Runtime engine" card hint, and the Server tab status strip. I did not
  reuse `RunningElsewhere` or `useGenerationProgress`: they poll their own endpoint and their hint text is written for a
  studio screen; the workspace payload already carries the data.
- Strings: `serverTab.engineBusy.*` in `common.json` (en text, null in the other 10 locale files).
  They are in `common` and not under `dashboard.*` because the Server tab and the sidebar already use that namespace
  and the Dashboard borrows them; no key was added to `dashboard.json`.

## Verified on screen (Mac, own backend on 8879, vite on 8924, storyboards in a throwaway folder)

- S4: a real Qwen-Image 2.1 sd.cpp run (768x640) started from a Storyboard batch. Sidebar footer, Dashboard card and
  Server tab all showed "Image engine busy: Qwen-Image-2.1 · sd.cpp Q4_K · 768x640 · sd.cpp · step N of 40" while the
  workspace said Idle and `loadedModelName` was null. Footer went back to "No model loaded" after the run stopped.
- S3: killed the backend (SIGKILL, with the sd.cpp child) mid-batch. The file on disk stayed `running` / `queued`.
  After restart, without opening anything, the file already had shots `idle`, batch `interrupted`, results `cancelled`
  with the note (start-up hook). The project page then showed no running shot and "Batch interrupted (the app closed)".
