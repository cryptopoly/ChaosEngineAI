Branch `v0100/d`, from `release/v0.10.0`. Plan: `docs/plans/v0.10.0-storyboard-polish.md`, package S-D.

## Done

### S8 Plan tab (film from an idea)
- A new project tab, **Plan**, second after Overview. Why a tab and not a panel on Storyboard: planning is the step before
  the board, it holds two conversations (per shot and for the whole film) that need room, and the board's shot cards
  (agent F) stay as they are. Overview's first step now offers "Plan from an idea" as the main button.
- Brief (free text, saved as an op on blur), length chips (Any, 15 s to 2 min), shot count (4 to 8 or "the model
  chooses"), and style pictures (drop, file, gallery, a shot still; they become the project's style references, S15).
- "Propose shots" asks the loaded chat model through `state.runtime.generate` (the path Chat and the Chat Studio tools
  use), with a JSON schema, the brief, the format, the cast, the style words and palette, and the style pictures when the
  loaded model reads images. The proposal shows each shot, the total against the length asked, and the model's note;
  nothing is written until "Use these N shots" (or "Add after" / "Replace", which asks first when shots with takes would
  leave the board, and is off while a shot is locked).
- Every shot is editable in place (title, length, picture prompt, movement), each field saved as an `edit_shot` on blur.
  "Rework with the model" opens a short chat for that shot: the model returns a new prompt and why; "Use this" applies
  only the fields it changed as one edit.
- Direction chat (right column, below on narrow screens): kept with the project (`planChat`, not part of Undo). The
  model answers in words and may propose edits, additions and removals across shots (by shot number, mapped to ids on
  the server, locked shots skipped); they are listed in plain words and applied as one `plan_changes` op.
- No chat model loaded: a plain callout with the installed chat models and a Load button that loads in place (the app
  stays on Plan). A model call refused for no model points back to it.
- Backend: `storyboard/planner.py` (prompts, schema, cleaning: lengths cut, one-line titles, seconds 1 to 10, unknown
  shot numbers dropped), routes at the end of `routes/storyboard.py`: `GET .../plan/status`, `POST .../plan/propose`,
  `.../plan/rework`, `.../plan/direct`, `GET /api/storyboard/fonts`. Errors carry `detail.code`
  (`no-model`, `busy`, `no-brief`, `bad-reply`, `model-error`).
- Ops (`storyboard/plan_ops.py`, registered in `ops.py`): `set_plan`, `apply_plan` (append or replace, one Undo),
  `plan_changes` (edits, adds, removals, one Undo), `add_plan_message` and `clear_plan_chat` (not undoable),
  `set_brand` (one Undo).

### S15 Style reference and brand kit
- New reference kind `style` (`references.styles`), with `palette` read from its pictures by a local k-means on a 64 px
  copy (`storyboard/palette.py`; Pillow and numpy, no network). Colours are ranked by coverage lifted by how colourful
  they are, so a grey wall does not push out the amber of the tea; the palette is read again when the pictures change and
  the user can take a colour out.
- Brand kit (`brand`): optional logo (copied into `media/brand/`), logo corner, caption look (font from the fonts
  installed on this machine, read with Pillow; colour from the palette, white, black or any; top, middle or bottom), and
  how shots use the style: Automatic, Always as words, Off.
- Shots use the style (`storyboard/style.py`, hooked into `generators.make_still` and `make_clip`): as reference pictures
  when the still model takes them (mflux `reference_image_limit`, in the slots the shot's cast leaves free), otherwise as
  words appended to the prompt ("Visual style: ...; colour palette of ..."). A text-to-video clip gets the words too.
  The take records `settings.style` (`pictures` or `words`), the Plan shot row shows a "Style as words / as pictures"
  badge, and the Plan tab says before anything renders which way the project's still model takes it.
- Cast tab: a "Style" group beside characters and places (same cards, plus the palette), and the Brand kit panel with a
  live preview of the caption and logo drawn on the first style picture.

### Format and compatibility
- No schema version bump. New fields have defaults (`plan`, `brand`, `planChat`, `references.styles`,
  `Reference.palette`), so every older project loads unchanged (tested). As with S6, an older app build refuses a project
  saved by this one (unknown fields).
- `store._TOP_KEYS` gains `plan` and `brand` so Undo and Redo cover them; `planChat` is deliberately not diffed.
- Bundles carry style pictures and the logo (`bundle.referenced`).
