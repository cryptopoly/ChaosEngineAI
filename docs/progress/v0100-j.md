# v0.10.0 package S-J: Chat plan card (item 1)

Branch `v0100/j`, cut from `release/v0.10.0`. Not merged; the integrator merges.

## What QA found (docs/progress/v0100-i.md, "Chat plan card")

- After a reload (or leaving the thread) a waiting plan card was gone and the turn sat up to 30 minutes.
- A running thread was listed as "New chat" until its reply ended.
- A first call refused by the pre-check (`storyboard_generate` with `what: "stills"`) showed as a folded tool line;
  if the model gave up, the user saw "the model called storyboard_generate, no card, no batch".

## Causes and changes

1. **Card after a reload.** The turn ran inside the HTTP stream's generator, so a closed stream either stopped
   feeding it (the turn hung on the card with nobody able to answer) or closed it (the plan was dropped). Now, with
   studio tools on, `generate_stream` runs the turn on its own thread and the response only relays its frames
   (`_studio_detached_stream` in `backend_service/state/generation.py`). A closed stream leaves the turn running;
   Stop still cancels it, and an unanswered card still gives up after the gate's 30 minutes.
   New route `GET /api/chat/studio/sessions/{id}/turn` (`routes/chat.py`) gives `running` and the plans that wait
   (`studio_gate.pending_for_session`, `turn_started/turn_ended/turn_running`).
   Frontend: `src/features/chat/detachedTurn.ts` (`useDetachedTurn`, used in `useChat`) polls that route every 2 s
   for the open thread when its last message is the user's and this window is not streaming it. The waiting cards
   show under the user's message ("This reply is waiting for your answer to the plan below."); the click answers the
   same turn; the thread counts as busy (composer off, Stop cancels the backend turn); when the turn ends the
   workspace is refreshed and the saved reply shows.
   Behaviour change against D-60's note "a closed stream ends a plan's wait": the old test
   `test_closing_the_stream_cancels_a_waiting_plan` is replaced by
   `test_closing_the_stream_leaves_the_plan_waiting_for_the_reloaded_window` and `test_stop_still_cancels_a_waiting_plan`.
2. **Title of a running thread.** The backend set the title at the start of the turn but saved it only at the end,
   and the window kept its local "New chat" until the done event. Now the session is saved when the turn starts, and
   `appendOptimisticTurn` names an untitled first turn from the prompt (same `titleFromPrompt` the app uses; a
   second thread with the same words gets "(2)").
3. **Refused first call.** `StudioJobCard` shows a "Not started" notice with the reason in full and "The model was
   told why and can fix the call." (`refusalReason` in `studioChat.ts`; ChatThread routes studio errors to it).
   The same turn already gave the model the tool answer; the next user turn did not, because the history keeps no
   tool results. `_build_history_with_reasoning` now adds one line per studio call refused before it ran
   (`[storyboard_generate was not run: <reason>]`), unless the same tool ran later in that turn.

New strings (chat namespace, en only, null elsewhere): `studioChat.job.notStarted`, `studioChat.job.notStartedHint`,
`studioChat.detached.waiting`, `studioChat.detached.running`.
