# v0.10.0 S-L: clean-up panel (item 6)

Branch `v0100/l` (from `release/v0.10.0`). Not merged.

## Done
- `backend_service/routes/cleanup.py`, registered in `routes/__init__.py`.
  - `GET /api/cleanup/items`: `{projects, threads, outputs}`.
    - projects: `id, name, shots, bytes` (files under the project folder, links not followed), `lastEdited` (project.json mtime, epoch seconds). Unreadable projects are not offered.
    - threads: `id, title, messages, bytes` (size of the thread as stored), `lastUsed` (newest message time, else the thread's updatedAt label; epoch seconds or null).
    - outputs: `id` (`image:<path under the image folder>` or `video:...`), `kind, name` (prompt start), `bytes` (metadata plus media), `createdAt`.
  - `POST /api/cleanup/delete` `{projects, threads, outputs}` (ids only, extra fields refused with 422, empty request 400). Answers `{results[], deleted, refused, freedBytes}`; each result row has `kind, id, name, ok, bytes, reason`.
- Safety: every id is looked up (exact string match) in a fresh listing built from the backend's own folders; an id not in it is "Not found" and touches nothing. No path is ever built from a request id. Gallery media are the files next to the metadata with the same name and a known extension (the `imagePath` / `videoPath` inside the metadata is ignored); a file is removed only if it is a real file whose resolved path is under its gallery root. Linked folders and files are skipped. Projects go through `ProjectStore.delete` (its own root check). Chat threads go through `state.delete_session`.
- Refusals: a project with a batch in `LIVE_BATCHES` ("A batch is running for this project. Cancel it or wait, then delete.") or a running render is refused; the rest of the request still runs.
- Frontend: `src/api/cleanup.ts`, `src/features/settings/cleanupLogic.ts` (pure ticking and totals), `CleanupPanel.tsx` (`CleanupView` draws, `CleanupPanel` holds state). Placed in Settings > Disk under the disk usage panel. Fieldset and legend per group, a labelled checkbox per row (the label is the row text), a select-all per group (indeterminate when part ticked), nothing ticked by default, the Delete button disabled until something is ticked, a `ConfirmDialog` (alertdialog, focus trap, Escape cancels) naming the count and total size with "It cannot be undone", then a `role="status"` result note listing refused items with reasons. Strings in `src/locales/*/common.json` under `settingsTab.cleanup` (en text, null in the other 10).
