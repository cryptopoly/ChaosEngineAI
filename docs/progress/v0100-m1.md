# v0.10.0 package S-M1: long projects, backend (item 8)

Branch `v0100/m1`, from `release/v0.10.0`. Plan: `docs/plans/v0.10.0-eight-improvements.md`, package S-M1.
Backend only; S-M2 builds the freestyle board UI on the contract below.

## API contract (for S-M2)

All routes are under `/api/storyboard/projects/{projectId}`. Routes that change a project take the `revision` the
caller last saw; a stale one answers 409 `{message, revision, project}` like every other storyboard route. Errors
are `{detail: string}` (400 bad input, 404 unknown, 409 busy or wrong state) unless noted.
TypeScript types: `src/types/storyboard.ts`; client functions: `src/api/storyboard.ts` (names given below).

### 1. Durable batch queue (pause, resume, survive a restart)

Batch states (`BatchRecord.state`, `StoryboardBatchState`):
`"queued" | "running" | "paused" | "done" | "failed" | "cancelled" | "interrupted"`.

- `paused`: the batch stopped between two steps and keeps its remaining steps. It got there by Pause
  (`pauseReason: "user"`) or because the app stopped while it ran (`pauseReason: "restart"`).
- `interrupted` (S3) is now only for a batch that stopped with nothing it can resume.

New `BatchRecord` fields (all optional in old files):

```jsonc
{
  "pausedAt": 1763300000.0,       // epoch seconds of the last pause, or null
  "pauseReason": "user",          // "user" | "restart" | null
  "resumedAt": 1763300100.0,      // epoch seconds of the last resume, or null
  "resumes": 1                    // how many times it was resumed
}
```

The remaining steps are the `results` with `state: "queued"`, in order (stills first, then clips). A result keeps
`takeId` when its step finished, so a clip step after a resume still completes the take its still started.

On start-up (and on every project load, as in S3), a batch left `queued` or `running` by a process that is gone becomes
`paused` with `pauseReason: "restart"`:
- its `running` step goes back to `queued` (a still or clip is only stored when it finishes, so the step restarts);
- a step that cannot resume becomes `cancelled` with a note (the S3 reconcile): its shot was removed, or it is a clip
  whose still this batch made and that take or its file is gone;
- if no `queued` step is left the batch becomes `interrupted` (S3 behaviour);
- shots left `queued` / `running` go to `done` (has a take) or `idle`, as in S3. Which shots are still waiting is read
  from the paused record's queued results.

Routes:

| Route | Body | Answer |
|---|---|---|
| `POST .../batches/{batchId}/pause` | none | `{"pausing": true}`; the run stops after the step in progress, then the record is `paused`. 404 when the batch is not running. Client: `pauseStoryboardBatch` |
| `POST .../batches/{batchId}/resume` | `{"revision": int}` | Same as `POST .../batches`: `{"batchId", "batch", "revision", "progress"}`. 409 when the batch is not `paused` or is already running. 400 when no remaining step can run (the record is left as it was; cancel it). Client: `resumeStoryboardBatch` |
| `POST .../batches/{batchId}/cancel` | none | `{"cancelled": true}`. Also works on a `paused` batch now: it becomes `cancelled` and its queued results `cancelled`. Client: `cancelStoryboardBatch` (unchanged) |
| `GET .../batches/{batchId}` | none | `{"batch", "revision", "progress"?}`. `progress` is now also given for a `paused` batch (below). Client: `getStoryboardBatch` |

Batch bar data (`progress`, `StoryboardBatchStatus.progress`). A live batch gives what it gave before, with the counts
now covering the whole batch across resumes (`totalSteps` counts every non-skipped step, `step` the finished ones plus
the one running). A paused batch gives:

```jsonc
{
  "paused": true,
  "pauseReason": "restart",
  "totalSteps": 12,
  "step": 5,                 // steps finished (done or failed)
  "remainingSteps": 7,
  "remaining": {"still": 2, "clip": 5},
  "etaSeconds": 840,         // only when there is a basis
  "etaBasis": "clips"        // "clips": from steps this batch finished; "project": from other takes of this project
}
```

The time left is priced per kind: the mean measured seconds of this batch's finished steps of that kind, else the mean
of this project's takes of that kind, else none (no `etaSeconds`).

### 2. Song attached to a project

New model field `Project.song` (`StoryboardSong | null`, default null; Undo covers it):

```jsonc
{
  "path": "media/song/song-1763300000123.flac", // inside the project folder
  "hash": "<sha256>",
  "title": "Night drive",
  "seconds": 212.4,
  "bpm": 118.0,                // null when no steady beat was found
  "beats": [0.51, 1.02, ...],  // seconds, rounded to ms
  "sections": [{"start": 0.0, "end": 14.2, "label": "intro", "energy": 0.31}, ...],
  "lyrics": ["first line", "second line"],
  "clipId": "a_1a2b3c4d",      // the music clip it put on the mixer, or null
  "libraryId": "1763290000_ab12cd34", // when it came from the Music library, else null
  "rough": true,               // the analysis is an estimate (always true for now; see note)
  "note": "Sections and tempo are estimated from loudness and onsets; check them by ear.",
  "analysedAt": 1763300000.0
}
```

Section labels: `intro`, `outro`, and letters `A`, `B`, `C`... for the parts between (sections that sound alike get the
same letter). `energy` is 0 to 1 (relative loudness of that part in this song).

| Route | Body | Answer |
|---|---|---|
| `POST .../song` | `{"revision": int, "libraryId"?: string, "path"?: string, "title"?: string, "addToMixer"?: bool (default true)}` exactly one of `libraryId` / `path` (`path` is a local file or an `upload:` handle) | `{"project", "timeline", "analysis": {"seconds", "bpm", "beats": int, "sections": [...], "rough", "note"}}`. 400 for a file that is not audio by its bytes (WAV, FLAC, MP3, OGG, M4A/AAC), too short (under 5 s), too long (over 1200 s, 20 minutes) or unreadable. 409 `{code, message}` when ffmpeg is missing (same as render). Replaces an earlier song; with `addToMixer` the old song's mixer clip is replaced too. Client: `attachStoryboardSong` |

Ops (through `POST .../ops`, all undoable):
- `edit_song`: `{"title"?, "bpm"?, "clearBpm"?: bool, "sections"?: [{start, end, label, energy?}], "lyrics"?: string[]}` (edit sections by hand, set lyrics; sections are sorted by start and must end inside the song).
- `clear_song`: `{"removeClip"?: bool (default true)}`.
- `set_song` is what the route runs; a caller does not need it.

### 3. Cut plan from the song

| Route | Body | Answer |
|---|---|---|
| `POST .../cut-plan` | `{"maxShotSeconds"?: number, "minShotSeconds"?: number (default 2), "keepPrompts"?: bool (default true)}` | below. 400 when the project has no song. Nothing is written. Client: `proposeStoryboardCutPlan` |

```jsonc
{
  "shots": [  // StoryboardPlannedShot, plus trimOut so the clip is cut to the music
    {"title": "A 1", "stillPrompt": "", "motionPrompt": "", "seconds": 3.05, "trimOut": 3.05, "referenceImages": []}
  ],
  "mode": "replace",
  "totalSeconds": 212.4,
  "clipSeconds": 4.0,          // the longest shot allowed
  "clipSecondsSource": "model",// "model" (the project's video model in the catalog) | "request" | "default" (4 s)
  "videoModel": "LTX-2.5 distilled", // name, or null
  "sections": [{"start", "end", "label", "shots": 5}],
  "note": "Cuts fall on beats ...",
  "rough": true
}
```

Apply it with the ordinary op `apply_plan` `{"mode": "replace", "shots": <shots>}` (one Undo). `apply_plan` now takes up to
500 shots (was 12) and each planned shot may carry `trimOut`. With `keepPrompts`, the n-th proposed shot carries the
prompts and references of the project's n-th shot when there is one.

### 4. Lyric captions

Lyrics are `song.lyrics` (set with `edit_song`; a song from the Music library brings its lyrics, structure tags such as
`[verse]` dropped).

| Route | Body | Answer |
|---|---|---|
| `GET /api/storyboard/lyrics/speech` | none | `{"ready": bool, "reason": string \| null}` whether speech-to-text alignment can run here. Client: `getLyricsSpeechStatus` |
| `POST .../lyrics/captions` | `{"revision": int, "timing"?: "auto" \| "sections" \| "speech" (default auto), "language"?: string}` | `{"project", "timeline", "timing": "sections" \| "speech", "notes": string[]}`. `auto` uses speech when it is ready, else sections, and says why in `notes`. `speech` when it is not ready: 409 `{code: "no-stt", message}`. 400 when there is no song, no lyrics, or the song is not on the mixer. Client: `makeStoryboardLyricCaptions` |

The captions are written with the existing `set_captions` op on the song's mixer clip (so they follow the clip and one
Undo removes them), replacing that clip's earlier captions. Burn-in and `.srt` are the existing switches
(`export.captionsBurn`, `export.captionsSrt`) and `POST .../captions/export`; the look is the brand caption look.

### 5. Agent tools

- `storyboard_batch`: `action` `status | pause | resume | cancel`, `project_id`, `batch_id`, `revision` (resume). Resume
  returns a job id like `storyboard_generate`.
- `storyboard_song`: `action` `attach | get | edit | remove | cut_plan | lyrics | lyric_captions`; `attach` takes
  `library_id` or `path` (upload handle or app output file); `cut_plan` with `apply: true` applies it.
