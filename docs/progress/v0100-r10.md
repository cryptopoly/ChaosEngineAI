## Why `platforms` without `"cuda"` (and not per-row `unavailableReason`)

Removing `"cuda"` is one source of truth: the fit function already treats a row without the host's platform as "does not run here", the "Apple Silicon / CUDA" platform chips stop advertising a lane that does not exist, and nothing else needs a second field kept in step. A per-row `unavailableReason` would repeat the runtime's sentence 4 times and could drift. The runtime-level reason (already read by the Studio, Sounds and Models pages) is the single place the sentence is shown.

Note: the `fit` payload for these rows is still `unknown` with the backend text "This model does not run on an NVIDIA GPU." (`helpers/music_fit.py`, not in my files). The chip text "Not for this machine" is shared (`FitBadge`, `library.json`), also not mine, so the Models page replaces the chip itself when the runtime reports the unsupported platform. Other pages are unaffected.
