## estimateRef (stable shape for wave 2: B, R7)

Optional on any image or video catalog row that has `estimatedGenerationSeconds`:

```
"estimateRef": {
  "width": int > 0, "height": int > 0,   # size the catalog figure was measured at
  "frames": int > 0,                     # images: always 1
  "steps": int > 0,                      # steps it was measured at
  "fixed": float in (0, 1),              # optional: share of the time that does not grow with the work
  "quad": number > 0,                    # optional: attention term; 1e9 switches it off (linear)
  "ignoresSteps": true                   # optional: engine runs a set schedule; the steps setting is ignored
}
```

- A row without `estimateRef` stays flat (Studio, job ETA) or, for Storyboard clips, keeps the old scale by clip length.
- Without `fixed`, the engine default applies: video 0.04 (Wan fit, CUDA), mflux 0.1, other image engines 0.6.
- `quad` default 53300. Both defaults live in `backend_service/helpers/time_estimate.py` and `src/utils/timeEstimate.ts`.
- Use it from Python as `variant_seconds(variant, kind, width, height, frames=1, steps=None)`; from TS as
  `variantSeconds(variant, kind, {width, height, frames, steps})`. Missing frames / steps count as the reference.
- New rows (task B): give `estimateRef` only when the row has a time. H3 has none, so no `estimateRef`.
- R7 (`storyboard/batch.py`): price a kind with no finished step via `storyboard.estimate.estimate()` or directly
  with `variant_seconds(variant, "video", project.defaults.width, project.defaults.height, frames)`; the frames the
  batch would ask for are `estimate._clip_frames(variant, shot, fps)`.
