Part 2, family table from `capabilities --json`:

- `_tensorfold_native.py`: `cached_capabilities(binary)` (probe once per path, size and mtime; a failed probe is retried), `serves_family`, `prefers_python`, `family_report(caps)`.
- `family_report`: one entry per `model_type` the binary lists (`servedHere: true`), joined to the rows of `TENSORFOLD_FAMILIES` and `NATIVE_MODELS`; a type no row names is `curated: false` and never offered, with the binary's formats. Then one entry per curated row none of whose types the binary lists (`servedHere: false`, `legacy: true` when the Python install still serves it). `offered`/`repos` come from the Mac table on a Metal build and from `NATIVE_MODELS` on a CUDA build.
- D-77: a new field `native_refuses` on the Gemma 4 26B-A4B row, because the Metal binary lists `gemma4` (31B, 12B) yet refuses the 26B-A4B by name, so the family list alone would wrongly move it. Routing rule: a `native=False` row goes to the 0.6.6 Python install while the binary does not list it, and to the binary once a release lists it (Gemma 26B stays on Python until `native_refuses` is cleared after a re-check). With no binary report the `native` flag answers as before. `native=True` rows always stay on the binary, which refuses an unknown checkpoint by name; the controller probes the binary only for `native=False` rows.
- Wired into the controller (`_tensorfold_engine`, the unavailable message, and the exclusive refusal, which now says the older Python install is missing instead of "TensorFold is not installed" when only that is missing), the native engine's family facts (drafter and vision), and the system payload's model list.
- `GET /api/setup/tensorfold-native-status` and `GET /api/setup/tensorfold-status` (native branch) return `families` (the report); the native status now uses the cached probe.
- `scripts/check-upstreams.py` `unlisted_families()` uses the same report (`curated: false`); on this Mac it reports none.
- E2E: the phase 1 check `TensorFold 1.2.7 families (FU-168)` first runs `scripts/e2e_phases/tensorfold_families.py` `family_report_check`: the status route's served families must equal the installed binary's own `capabilities --json` families, none uncurated; skips without a binary; on a CUDA host the check now passes on the report alone instead of skipping.
